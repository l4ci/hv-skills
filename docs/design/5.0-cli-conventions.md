# 5.0 `hv` CLI conventions

These rules hold for every `hv` verb. Per-verb flags and `--json` data shapes live in the verb contract (A2, #46) and must fit inside them. The command tree comes from the [helper triage](5.0-helper-triage.md). The Go code that enforces these rules is `internal/cli`.

## Invocation

```
hv [global flags] <group> <verb> [verb flags] [args] [-- literal args]
```

- Global flags may appear anywhere before `--`. `hv --json item show 12` and `hv item show 12 --json` are the same call.
- Verb flags use Go `flag` syntax: `--name value` or `--name=value`, and booleans as `--name` alone. Single-dash long forms (`-name`) also parse, but docs and skills always write two dashes.
- Any flag that takes a file path also accepts `-`, which means stdin. Bodies always come in this way (`--body-file -`), never as positional text.
- `hv` never prompts and never reads a TTY. A verb that needs a decision fails with usage (exit 2) and names the missing flag. Asking the human is the skill's job.

## Global flags

| Flag | Meaning |
|---|---|
| `--json` | Machine output: one JSON envelope on stdout (below). |
| `-C <dir>`, `--cwd <dir>` | Run as if started in `<dir>`, like `git -C`. Lets an orchestrator act on a worker's worktree without `cd`. |
| `--repo <name>` | Umbrella mode: scope the verb to the named registered sub-repo. A verb that has no repo scope rejects it with exit 2. Outside umbrella mode, any value is a resolution error (exit 3). |
| `-h`, `--help` | Help for the group or verb, on stdout, exit 0. |

`hv --version` is an alias for `hv version`. There are no colour, verbosity or quiet flags: output carries no ANSI codes, and stdout is already the quiet channel.

## Project root

A verb that needs `.hv/` walks up from the working directory (or `--cwd`) to the nearest directory that holds `.hv/`. In umbrella mode that is the umbrella root unless `--repo` is given. When no `.hv/` is found, the verb exits 3 with the hint `run: hv init`. Only `hv init`, `hv version`, `hv update` and help run without one.

## Output

Without `--json`, stdout carries human text: plain lines, lists one item per line, no colour, no tables wider than the data needs. Text output is for people and may change between releases. Skills that parse output use `--json`.

With `--json`, stdout carries exactly one JSON document followed by a newline, on success and on failure:

```json
{"ok": true, "data": { … }}
{"ok": true, "data": { … }, "warnings": ["…"]}
{"ok": false, "error": {"code": "not_found", "exit": 3, "message": "item 12 not found", "hint": "…"}}
```

- `data` is the verb's result, defined per verb in the contract. A verb with nothing to return sends `{}`. A list verb returns an object (`{"items": […]}`), never a bare array, so fields can be added later.
- A mutating verb reports `"changed": true|false` in `data`. An idempotent no-op is a success (`ok: true`, exit 0, `changed: false`).
- `warnings` is present only when non-empty. Each warning also goes to stderr.
- `error.code` is the name from the exit-code table, `error.exit` is the process exit code, and `hint` is optional.
- Field names are camelCase, matching `config.json` (`mergeStrategy`, `loopStartedAt`). Dates are `YYYY-MM-DD` and timestamps are RFC 3339 in UTC. Item IDs are strings (`"B07"`, or `"12"` in issue mode), so the two backends share one shape.
- Shapes change only additively within a major version. Removing or retyping a field is a breaking change.

## stderr

stderr is always text for people, never JSON, with or without `--json`:

```
hv item show: item 12 not found
hint: run hv backlog list to see open items
hv backlog drift: warning: 3 commits reference closed items
```

The first line is `hv <group> <verb>: <message>`, with `warning:` before the message for warnings. An optional next line starts with `hint:`. On failure the stderr line and `error.message` carry the same text.

## Exit codes

| Exit | `error.code` | Meaning |
|---|---|---|
| 0 | | Success, including idempotent no-ops. |
| 1 | `failed` | The verb ran and the answer is no: a guard or check failed (`dirty tree`, `item not ready`, `release blocked`). Nothing was changed. |
| 2 | `usage` | Bad invocation: unknown group or verb, unknown or missing flag, malformed argument. |
| 3 | `not_found` | Something named or required could not be resolved: item, milestone, plan key, sub-repo, base branch, or the `.hv/` root itself. |
| 4 | `refused` | A mutating verb refused to break an invariant it enforces: the target already exists, the operation would run on the base branch, proof is missing, a manual gate is not cleared. |
| 5 | `unavailable` | An external dependency is missing or failing: `git`, `gh`, `glab`, auth, network, or the tracker. |
| 6 | `retry` | A transient condition that a later retry can clear: a rate limit, or a lock held past its timeout. |
| 70 | `internal` | A bug in `hv`: unexpected state or an unhandled error. Report it. |
| 71 | `not_implemented` | The verb is in the tree but not ported yet. Only exists until A9. |

Use 1 when the verb exists to answer a question, and 4 when the verb exists to change something and declines to. A verb that hits a corrupt or unreadable state file exits 70, unless the contract defines a recovery for it.

## Writes

- Every write is atomic: write `<path>.tmp` in the same directory, then rename it over `<path>`. Readers never lock.
- A read-modify-write takes an exclusive advisory `flock` on the sibling `<path>.lock`, never on the data file, because the rename swaps the inode. The lock is retried every 50 ms for up to 10 s, then the verb exits 6. The empty `.lock` file stays in place. This matches `hvlib_io.locked`, so `hv` and the old helpers can share a file during the port.
- JSON state files are written the way Python's `json.dumps(data, indent=2)` writes them: two-space indent, key order preserved, `\uXXXX` for non-ASCII, and a trailing newline. A file round-tripped through `hv` produces no diff.

## Config

`.hv/config.json` is read with `.hv/config.local.json` deep-merged on top. Nested objects merge by key. A scalar, an array, or a value whose type differs from the base replaces the base value. A missing or unparseable file counts as absent. This matches `hvlib_io.load_config`, and a Go test compares the two on a shared fixture.
