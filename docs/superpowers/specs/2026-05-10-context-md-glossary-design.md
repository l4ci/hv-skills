# CONTEXT.md: project-level domain glossary

**Status:** Draft, awaiting user review
**Date:** 2026-05-10
**Owner:** hv-skills
**Tracking item:** [F38]
**Related:** [T21] (grill-with-docs mining), [F39], [F40] (sibling follow-ups)

## Problem

hv-skills tracks durable learnings (KNOWLEDGE.md), hard boundaries (DECISIONS.md), subsystems (MAP.md), and backlog (TODO.md) — but not *terminology*. Domain concepts get named differently in different turns of a session, in different captured items, and in different commits. The AI uses one phrasing in `/hv-work`, the user uses another in `/hv-capture`, and the project drifts away from a shared vocabulary.

The grill-with-docs pattern names the gap directly: *"When the user uses a term that conflicts with the existing language in CONTEXT.md, call it out immediately."* That requires CONTEXT.md to exist as a first-class artifact.

## Goal

Add CONTEXT.md as a project-level domain glossary alongside KNOWLEDGE / DECISIONS / MAP. Capture *terminology* — canonical names for domain concepts, sharpened over time. AI consults it before answering or brainstorming so terms stay consistent; the AI also flags conflicts inline when the user's wording deviates from the canonical term or its meaning. Writes happen inline as terms resolve, not batched end-of-session.

## Non-goals

- No end-of-session sweep for missed terms. Writes are explicit-signal-only; if a term wasn't captured in flow, the user invokes `/hv-context` to add it.
- No auto-generated alias suggestions. Aliases are user-stated.
- No embeddings or semantic search. Lookup is by name and listed alias only.
- No soft caps or staleness detection in v1 (could land later via `hv-staleness context --days N`).
- No cross-link to KNOWLEDGE/DECISIONS bullets that mention a term.
- No cross-project glossary sharing.

## Design

### Decisions taken during brainstorming

These four decisions shape the rest of the design and are settled (not open for re-litigation in implementation):

1. **Write trigger is explicit-signal-only.** AI writes inline only when the user produces an unambiguous definitional phrase. AI never auto-proposes a term capture from implicit usage.
2. **Skill form is both `/hv-context` slash command + `bin/hv-context-add` inline helper.** The helper writes; the slash command is the deliberate entry point for batch additions, edits, and disambiguation.
3. **Conflict scope is synonym + drift.** Both kinds get flagged inline (synonym detection from listed aliases is exact; drift detection is best-effort judgment).
4. **Umbrella mode is in v1.** Per-sub-repo CONTEXT.md plus an umbrella-shared CONTEXT.md and a CONTEXT-MAP.md pointer index.

### File layout

**Single-repo:**

```
.hv/CONTEXT.md
```

**Umbrella:**

```
.hv/CONTEXT.md                       # umbrella-shared cross-repo terms
.hv/CONTEXT-MAP.md                   # pointer index (auto-generated)
.hv/contexts/<repo>/CONTEXT.md       # per-sub-repo glossary
```

A single-repo project that later becomes an umbrella keeps `.hv/CONTEXT.md` as the umbrella-shared file; per-sub-repo files are added under `.hv/contexts/`.

### Entry shape

```markdown
# Context

## <term>

<one-paragraph canonical definition — single paragraph, complete sentences>

**Aliases:** <comma-separated synonyms>
**Not:** <comma-separated near-misses>

<!-- 2026-05-10 -->
```

- Term headings are lowercase by convention (matches code/identifiers); term names with capitalization (e.g., proper nouns, acronyms) are written as the user stated them.
- Terms ordered alphabetically (case-insensitive) within the file.
- The `**Aliases:**` line is **always present** — it's the regex anchor for synonym detection. When there are no aliases, write `**Aliases:** _none_`.
- The `**Not:**` line is optional; omit the line when there's nothing to distinguish.
- Date stamp is an HTML comment, mirrors KNOWLEDGE convention.

### CONTEXT-MAP.md (umbrella only)

Auto-generated pointer index. Lists each CONTEXT.md file and its term names. Manual edits are overwritten on next regeneration.

```markdown
# Context Map

_Generated by `hv-context-map`. Manual edits are overwritten._

## Umbrella-shared (.hv/CONTEXT.md)
- backlog
- decision
- session

## repo-a (.hv/contexts/repo-a/CONTEXT.md)
- agent-loop
- prompt-stage
- token-budget

## repo-b (.hv/contexts/repo-b/CONTEXT.md)
- ledger
- payout-cycle
```

### Bin helpers

Four helpers, three of them following established `hv-knowledge-*` / `hv-map-*` patterns; one new.

**`bin/hv-context-query <term>...`** — mirror of `hv-knowledge-query`. Prints matching `## <term>` sections.

- Single-repo: queries `.hv/CONTEXT.md`.
- Umbrella: queries `.hv/CONTEXT.md` (umbrella-shared) **and** the active sub-repo's `.hv/contexts/<repo>/CONTEXT.md` (repo resolved via `bin/hv-resolve-repo`). De-dups by term name; sub-repo entry wins on conflict, with a stderr note.
- Each printed section is preceded by a `> from: <relative-path>` line so the AI knows which file the entry came from.
- Backed by a new `context` key in `bin/hv-section-query`'s file-routing table.

**`bin/hv-context-index`** — regenerates the `<!-- hv-context-start -->...<!-- hv-context-end -->` managed block in CLAUDE.md.

- Block format includes term + aliases + first-sentence gloss so the AI has enough signal in the always-on context to detect both **synonym** conflicts (alias match) and **drift** conflicts (gloss mismatch) without any helper call:
  ```markdown
  <!-- hv-context-start -->
  ## Project Context

  Domain terminology lives in `.hv/CONTEXT.md`. Use these canonical names; if a term you're using conflicts (synonym or drift), call it out.

  - **backlog** *(aka task list, todo list)* — the canonical project queue (.hv/TODO.md), zero-padded IDs
  - **decision** — a hard project boundary captured in DECISIONS.md
  - …
  <!-- hv-context-end -->
  ```
- Format rules:
  - `*(aka <list>)*` parenthetical is omitted entirely when the entry has no aliases (i.e. when source has `**Aliases:** _none_`).
  - "First-sentence gloss" is the leading sentence of the term's definition paragraph. If the sentence exceeds 160 characters, hard-cut at the last word boundary ≤ 160 and append `…`. The AI is responsible for writing definitions whose first sentence stands alone.
- **Single-repo:** flat list of terms.
- **Umbrella:** umbrella-shared terms listed first, then `### <repo>` sub-heading with the active sub-repo's terms. The active sub-repo is resolved via `hv-resolve-repo` at index time; running `hv-context-index` from a different cwd produces a different block. When the user is at the umbrella root (no active sub-repo), only umbrella-shared terms appear — sub-repo terms are not included. (This matches how active-branch state is already cwd-sensitive.)
- Side-effect of `hv-context-add`: when `hv-context-add` calls `hv-context-index` post-write, it uses the cwd of the calling shell to determine the active sub-repo.
- Backed by a new entry in the `REGISTRY` of `bin/hv-managed-block`. Because the body builder needs entry-body parsing (gloss + alias extraction), not just topic-name listing, the `context` key uses `--body-stdin` mode with a small Python renderer.

**`bin/hv-context-add <term> --def <text> [--alias <a>,...] [--not <n>,...] [--repo <name>] [--touch]`** — inline writer.

- If the term exists, edits in place: replaces the definition, merges aliases (union, deduped), merges nots (union, deduped). Date stamp is preserved unless `--touch` is passed.
- If the term is new, inserts alphabetically.
- `--repo` flag selects the target file in umbrella mode:
  - `--repo umbrella` (or omitted with no active sub-repo) → `.hv/CONTEXT.md`
  - `--repo <name>` → `.hv/contexts/<name>/CONTEXT.md`
  - `--repo` omitted with active sub-repo → active sub-repo's file (resolved via `hv-resolve-repo`)
- After write, internally calls `hv-context-index` (and `hv-context-map` in umbrella mode) to refresh derived artifacts.
- Exits 0 on success; non-zero with stderr message on conflicting alias collision (one alias maps to two different terms — refuses to write, asks user to resolve).

**`bin/hv-context-map`** *(umbrella only)* — regenerates `.hv/CONTEXT-MAP.md` by walking every CONTEXT.md file and listing term names per file.

- Called automatically by `hv-context-add` after each umbrella-mode write.
- Called by `/hv-init` when scaffolding an umbrella project.

### `hvlib` additions

- `iter_terms(text)` — mirrors `iter_topics`; yields `(term_name, body)` pairs.
- `parse_term_entry(body)` — extracts `definition`, `aliases: list[str]`, `nots: list[str]` from a section body. `**Aliases:** _none_` parses as empty list.
- `first_sentence(text, max_chars=160)` — leading sentence; if longer than `max_chars`, hard-cut at the last word boundary ≤ `max_chars` and append `…`.

### `/hv-context` skill

User-invocable. Parallels `/hv-decide` in shape (deliberate, manual, with confirmation).

**Phases:**

1. *Resolve* — figure out term + definition (from user input, or interactive `AskUserQuestion`).
2. *Check for conflicts* — search existing CONTEXT.md for the term and any alias overlap. If found, show the existing entry and ask: keep / replace / merge.
3. *Write* — call `bin/hv-context-add`.
4. *Index* — refresh CLAUDE.md managed block (handled by hv-context-add). In umbrella mode, also refresh CONTEXT-MAP.md.
5. *Commit* — single atomic commit `docs(context): add <term>` (new) or `docs(context): refine <term>` (edit).

**One-shot form:**
```
/hv-context backlog "the canonical project queue (.hv/TODO.md)" --alias "task list,todo list"
```
Skips `AskUserQuestion`; goes straight to phase 2.

**Banner:** standard hv-skill banner with the established emoji/triggers/pairs format.

### AI consultation & write behavior

This is the genuinely novel control plane — the rest mirrors existing patterns.

**Consult (every turn, free).**
The CLAUDE.md `## Project Context` block carries term + first-sentence gloss for every entry. Always loaded → always available. No proactive file reads needed.

For richer context (full definition, aliases, nots), the AI calls `hv-context-query <term>` on demand.

**Conflict-call-out — synonym detection.**
The always-on block carries aliases inline in `*(aka …)*` parentheticals (see `hv-context-index` format above). The AI matches the user's phrasing against the alias list directly from working memory — no helper call needed for the common case.

When detected, the AI flags inline:
> *"You said 'task list' — this project's CONTEXT calls this **backlog**. Want me to use that going forward, or run `/hv-context` to update the canonical name?"*

One-shot, not blocking. User answers in flow.

**Conflict-call-out — drift detection.**
Best-effort, judgment-based. AI compares the user's apparent meaning to the gloss in the CLAUDE.md block. If they diverge, it flags:
> *"You're using **decision** to mean a soft preference. CONTEXT defines **decision** as a hard boundary captured in DECISIONS.md. Did you mean a learning, or run `/hv-context` to refine the term?"*

False positives are tolerated (one-line interruption); false negatives are silently accepted. Drift detection is not blocking and is not required to fire on every potential drift — the AI errs toward not interrupting unless drift is clear.

**Write trigger — explicit signals only.**
AI writes inline (via `hv-context-add`) only when the user produces an unambiguous definitional signal. The recognized signals:

- *"let's call this X"* / *"the canonical name for this is X"*
- *"by X I mean Y"* / *"X means Y"* / *"X is our term for Y"*
- *"refine X — it should mean Y"* (existing-term update)
- Direct command: *"save X as Y"* / *"add X to context"* / *"update X in context"*

If the signal is ambiguous (the user mentions a term without defining it), AI does **not** write. It may ask one clarifying question; otherwise it proceeds without writing.

**No write trigger:**
- Implicit term emergence from discussion (deliberately ruled out — see decision 1).
- AI's own term coinage during explanation.
- Synonyms encountered during conflict-call-out (alias-additions go through `/hv-context` only).

### Skill integration touchpoints

| Skill | Read | Write | Notes |
|---|---|---|---|
| `/hv-vision` | yes (consult before brainstorming) | yes (vision sessions are the highest-yield write surface; explicit signals during brainstorming trigger inline `hv-context-add`) | Vision-time terms anchor the project's vocabulary |
| `/hv-work` | yes (read at task start when TODO entry uses domain terms) | only on explicit signal mid-cycle | Most cycles are read-only |
| `/hv-debug` | yes (read when investigating; bug reports often misuse domain terms) | only on explicit signal | Drift detection valuable here |
| `/hv-capture` | yes (re-write captured items to use canonical terms when sensible) | only on explicit signal | Helps keep TODO consistent |
| `/hv-init` | n/a | seeds empty `.hv/CONTEXT.md` + `## Project Context` managed block. In umbrella mode also seeds `.hv/contexts/<repo>/CONTEXT.md` per registered sub-repo and `.hv/CONTEXT-MAP.md` | One-time scaffold |

Implementation: each touchpoint skill gets a one-paragraph addition referencing CONTEXT consultation. No fundamental control-flow changes to existing skills.

### `/hv-init` integration

`/hv-init` Step 4 (Seed CLAUDE.md blocks) gains a new substep that calls `bin/hv-context-index` after KNOWLEDGE/DECISIONS/MAP indices.

`/hv-init` Step 2 (Bootstrap & Install Helpers) gains:

- Create `.hv/CONTEXT.md` with the `# Context` header and a placeholder line *(no terms yet — run `/hv-context` to add one)*.
- Umbrella mode: also create `.hv/contexts/<name>/CONTEXT.md` per registered sub-repo, plus `.hv/CONTEXT-MAP.md` (initial state via `hv-context-map`).

The `## Project Context` managed block, when CONTEXT.md is empty, renders:
```markdown
- _(no terms yet — run `/hv-context` to capture domain terminology)_
```

### Failure modes

- **Missing/corrupted CONTEXT.md** — helpers exit silently with a stderr warning. `/hv-init` re-creates the file if absent.
- **Conflicting alias** (one alias word maps to two different terms across files) — `hv-context-add` refuses the write with an explicit error; user resolves manually or via `/hv-context` merge flow.
- **Umbrella sub-repo not registered** — `hv-resolve-repo` returns empty; `hv-context-add --repo <name>` errors with a hint to run `hv-umbrella-init` or pass `--repo umbrella`.
- **Stale CLAUDE.md block** (e.g., user edited CONTEXT.md by hand without running index) — next `/hv-init`, `/hv-work`, or `/hv-context` invocation regenerates the block.

## Testing

End-to-end smoke test in `test/`:

1. **Single-repo init.** `/hv-init` → assert `.hv/CONTEXT.md` exists with `# Context` header and placeholder; `## Project Context` block in CLAUDE.md with the empty-state line.
2. **Add term.** `bin/hv-context-add backlog --def "the canonical project queue (.hv/TODO.md)" --alias "task list,todo list"` → assert entry inserted, alphabetical, dated; managed block regenerated with term + `*(aka task list, todo list)*` + gloss.
2a. **Add term without aliases.** `bin/hv-context-add session --def "an active hv-skills work cycle"` → assert source has `**Aliases:** _none_`; managed block omits the parenthetical.
3. **Query.** `bin/hv-context-query backlog` → returns the section with `> from:` prefix.
4. **Edit existing.** `bin/hv-context-add backlog --def "<refined>" --alias "queue"` → assert in-place edit, alias merge (union: task list, todo list, queue), original date preserved.
5. **Edit with --touch.** `bin/hv-context-add backlog --def "<refined>" --touch` → assert date stamp updated.
6. **Conflict — duplicate alias.** Add `inbox` with alias `task list` (already an alias of `backlog`) → assert non-zero exit with explanatory stderr.
7. **Umbrella init.** Scaffold a 2-repo umbrella → `/hv-init` → assert per-sub-repo CONTEXT.md + `.hv/CONTEXT-MAP.md` present.
8. **Umbrella write — sub-repo cwd.** From inside `repo-a`, `bin/hv-context-add agent-loop --def "..."` → assert write goes to `.hv/contexts/repo-a/CONTEXT.md`, CONTEXT-MAP.md updated, CLAUDE.md block lists umbrella-shared first then `### repo-a`.
9. **Umbrella write — explicit umbrella flag.** `bin/hv-context-add session --def "..." --repo umbrella` → assert write goes to umbrella-level `.hv/CONTEXT.md`.
10. **`/hv-context` skill** — fully-specified one-shot writes and exits 0; no AskUserQuestion when args are complete.

Plus unit tests:

- `test/test_hvlib_context.py` — `iter_terms`, `parse_term_entry`, `first_sentence` against fixture files.
- `test/test_managed_block_context.py` — body renderer for the `context` registry key with single-repo and umbrella inputs.
