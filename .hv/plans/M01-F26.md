# M01-F26 — design/plan/spike/vision CRUD triplet consolidation

## Goal

Extract a shared `bin/hv-artifact-show.sh` lib, retrofit the two existing show helpers, and add the two missing ones (`hv-vision-show`, `hv-spike-show`) so all four artifact families have API parity for show — zero callsite churn.

## Approach

Mirror the existing `bin/hv-artifact-rm.sh` precedent: a tiny sourced library exposing `hv_artifact_show <kind> <id-or-key> <dir>` that owns the `[ ! -f path ] && error >&2 && exit 1; cat path` pattern. Each show helper sources the lib via the same `. "$HERE/hv-artifact-show.sh"` idiom and delegates with its own family-specific path. Key validation stays inside each calling helper (`M\d{2,}` for vision, slug-shape `[a-z0-9][a-z0-9-]*` for spike) — the lib stays pattern-agnostic to match `hv-artifact-rm.sh`'s shape. List helpers are explicitly untouched: their projections genuinely differ per-family (git lookups, deps closures, milestone filters) and folding them would force per-kind branches inward. Smoke gains assertions in the two existing sections rather than a new section, following the `hv-artifact-rm.sh` precedent of testing-via-callers. Helper names don't change, so callsites across `hv-brainstorm`, `hv-review`, `hv-work` SKILL.md and docs need no edits.

## Assumptions

- The `hv-artifact-rm.sh` shape (source-after-preamble, single function `hv_artifact_<verb>`, args = `<kind> <id> <dir>`, `exit 1` on not-found via stderr) is canonical for sourceable artifact libs. `hv-artifact-show.sh` adopts it verbatim.
- All four families' detail-file paths are stable: `.hv/designs/<ID>.md`, `.hv/plans/<key>.md`, `.hv/spikes/<name>.md`, `.hv/milestones/<MID>.md`. The lib joins dir + key with no resolution logic.
- `hv-init`'s mirror picks up new `bin/hv-*` helpers automatically via its glob-based copy — no manifest edits needed.
- `hv-vision-show` uses strict ID matching (`M\d{2,}`) — fuzzy title lookup is deliberately out of scope per the design's open question.
- `hv-spike-show` uses the same slug regex (`[a-z0-9][a-z0-9-]*`) that `hv-spike-add` already enforces — each helper holds its own copy; a future refactor could extract to `hv-types.sh`.
