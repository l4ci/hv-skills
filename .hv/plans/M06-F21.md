# M06-F21 — Umbrella-aware KNOWLEDGE.md

## Goal

Umbrella users get per-sub-repo `.hv/knowledge/<repo>/KNOWLEDGE.md` storage with hybrid umbrella+sub-repo routing for learnings and Glossary terms, so `/hv-migrate v4` no longer refuses umbrella projects — while DECISIONS.md stays permanently umbrella-shared.

## Approach

Sidecar-files model (design's chosen Approach A in `.hv/designs/F21.md`), reconciled against post-F18 reality. A new `hvlib_knowledge.py` centralizes target-path resolution (`resolve_knowledge_target`, `resolve_tier_sidecar`). The **4** real `hv-knowledge-*` helpers (merge, query, tier, amend — *not* the nonexistent `hv-knowledge-index`) plus the 3 `hv-glossary-*` helpers gain `--repo umbrella|<name>` with auto-resolve fallback via `hv-resolve-repo` (cwd inside a sub-repo → that repo; umbrella root → umbrella). The CLAUDE.md knowledge block is extended inside `hv-managed-block` (no separate index tool exists post-F18). Per-sub-repo directories are created **lazily on first write** by the resolver (`hv-umbrella-init` never pre-created them — a stale design assumption), with a defensive seed in `/hv-init` umbrella setup. The tier sidecar **splits per file** (symmetric with the data-file split). `references/persistence-umbrella-scoping.md` is **created new** (the file the design says to "rename" no longer exists). `/hv-migrate v4`'s umbrella refusal is lifted; it already shells to `hv-glossary-import` (batch mode exists), so only the umbrella-branch routing is new. DECISIONS.md is untouched — the "Persistence-trio scoping" decision already locks it umbrella-only.

## Tasks

- **T1** — hvlib resolver foundation: `resolve_knowledge_target(repo="umbrella")` returns `.hv/KNOWLEDGE.md` for umbrella and `.hv/knowledge/<name>/KNOWLEDGE.md` for a registered sub-repo (mkdir -p on demand), raising on an unregistered name or sub-repo request when umbrella mode is off; `resolve_tier_sidecar(repo)` returns the parallel `knowledge-tier.json` path.
  - Files: create `bin/hvlib_knowledge.py`; `bin/hvlib.py` (re-export per the direct-path/no-cycle rule); mirror via `/hv-init` is automatic.

- **T2** — `/hv-learn` write routes by scope: `hv-knowledge-merge --repo <name>` writes to the sub-repo file; with no flag it auto-resolves the sub-repo from cwd (`hv-resolve-repo`), falling back to umbrella at the umbrella root.
  - Files: `bin/hv-knowledge-merge`; `hv-learn/SKILL.md` (routing UX — `--repo` flag + auto-resolve-or-ask at umbrella root, mirroring the F18 `/hv-learn --term` UX, not the removed `hv-context-add`).

- **T3** — Hybrid query: `hv-knowledge-query` inside a sub-repo returns umbrella + that sub-repo's bullets, each line carrying the existing `> from: <file>` prefix; at umbrella root it stays umbrella-only unless `--repo <name>` is given.

- This repo stays single-repo; F21 is validated via a synthetic umbrella fixture in smoke, never dogfooded here.
- DECISIONS.md is untouched — the "Persistence-trio scoping under umbrella mode" decision already locks it umbrella-only; T8's reference cites it rather than re-deciding.
- `/hv-migrate v4` already shells to `hv-glossary-import` (batch mode exists); only umbrella-branch routing and the refusal-lift are new.
- 9 tasks span multiple `/hv-work` cycles — this is a milestone-sized plan; tasks are sequential (T1 is the foundation all others consume).
