# M01-F25 — hvlib.py decomposition into flat hvlib_<name>.py modules

## Goal

Decompose `bin/hvlib.py` from 874 LoC to a thin re-export shim (≤80 LoC) by extracting 7 remaining concerns into flat `hvlib_<name>.py` modules across 8 dependency-ordered commits, each verified by a new import sentinel.

## Approach

F25 continues Rounds 1-3's flat-module + explicit-re-export pattern. Each extraction commit (a) creates `bin/hvlib_<name>.py` with the moved functions and a module docstring, (b) updates `bin/hvlib.py` to re-export the moved names via explicit `from hvlib_<name> import (...)` lines, (c) leaves all 73 PYTHONPATH heredoc callers untouched. An import sentinel (`test/sections/40_hvlib_exports.sh`) lands as T1 before any extraction — it enumerates the 40 names callers actively import and asserts each resolves via `from hvlib import X`. The sentinel runs after every commit; full `bash test/smoke.sh` runs at ship time per project convention.

Inter-module imports use the direct path (e.g. `from hvlib_section import find_section` inside `hvlib_crossref.py`), not through `hvlib`, to avoid circular-import risk during intermediate commits. The shim's job is one-way: shim re-exports from leaves; leaves never import from shim.

Per design Q1's default, `hvlib_milestone`'s 2 functions fold into `hvlib_repos` (both registry-shaped). `BACKLOG_FILE` and `git_mtime` stay in the shim per design Q3's default — both are small enough that extracting them buys nothing.

## Open questions

- **Sentinel granularity for `VERSION_KIND_REGISTRY`.** It's a constant, not callable. T1 strategy: sentinel imports the name and asserts `is not None`, not value equality. Semantic equality is out of scope for the sentinel.
- **Removing currently-unused public names.** `bin/hvlib.py` exports ~19 names callers never import (e.g. `infer_type_from_id`, `parse_related_ids`, `apply_cross_ref_strips`). Default: re-export them through the shim anyway; F25 is move-only, not a surface trim. A future `[F##]` can audit-and-trim.

## Assumptions

- Each `hvlib_<name>.py` module is **stdlib-only** plus inter-module imports of other `hvlib_<name>` modules (never `from hvlib import ...`, which would risk circular imports during intermediate commits).
- Function bodies move **verbatim** — no rewrites, no signature changes, no refactor inside a module during F25.
- The sentinel reads a static must-preserve name list committed in T1. New public names introduced post-F25 (by future work) are added to the sentinel separately.
- `BACKLOG_FILE = "BACKLOG.md"` and `def git_mtime(...)` stay in `bin/hvlib.py` so `hvlib.BACKLOG_FILE` and `hvlib.git_mtime(...)` work unchanged via attribute access.
- Each task's commit subject follows the established cadence: `refactor: extract hvlib_<name> [F25 T<n>]`.
- All 8 commits land on a single feature branch and merge as one PR per `.hv/config.json`'s `work.isolation: "branch"` setting; smoke runs at ship time via `/hv-ship`.
- PYTHONPATH heredoc body rewrites (F24's deferred 14 helpers) remain out of scope; future `[F##]` post-M01.
